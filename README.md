# A2-3-project-C

# 📊 AI 리뷰 감정 분석 & 비즈니스 인사이트 대시보드

> 고객 리뷰 데이터를 수집하고, AI 감정 분석과 통계·시각화를 통해
> **단순한 감정 분류를 넘어 비즈니스 의사결정에 활용할 수 있는 인사이트를 제공하는 CLI 기반 Python 애플리케이션**

---

## 1. 프로젝트 개요

수백~수천 건의 고객 리뷰를 사람이 직접 읽고 분석하는 것은 많은 시간이 필요합니다.

본 프로젝트에서는 Python과 AI API를 활용하여 리뷰 데이터를 자동으로 수집·정제하고,

* 감정(긍정/부정/중립) 분석
* 감정 신뢰도 분석
* 주요 키워드 추출
* 기간별 리뷰 요약
* 감정 변화 추이 분석
* 별점과 감정의 관계 분석
* TOP N 불만/칭찬 항목 분석
* 시각화 및 리포트 생성

까지 자동화합니다.

### 핵심 목표

> **"리뷰를 분류하는 프로그램"이 아니라
> "리뷰 데이터를 비즈니스 의사결정에 활용할 수 있는 정보로 변환하는 프로그램"을 만든다.**

---

# 2. 최종 결과물

최종적으로 다음 기능을 갖춘 **CLI 기반 Python 애플리케이션 1개**를 완성합니다.

```text
리뷰 파일
   ↓
Import
   ↓
Raw 데이터 저장
   ↓
Clean
   ↓
정제 데이터 저장
   ↓
AI 감정 분석
   ↓
감정 / 신뢰도 저장
   ↓
키워드 / 요약 추출
   ↓
통계 분석
   ↓
시각화
   ↓
대시보드 / 리포트
   ↓
CSV / JSONL / Excel Export
```

---

# 3. 핵심 기능

## 3.1 리뷰 데이터 수집 및 저장

* CSV / Excel 파일 입력
* 필수 필드: 리뷰 텍스트
* 선택 필드:

  * 별점
  * 작성일
  * 제품명
* 원본 데이터 Raw 저장
* 정제 데이터 Clean 저장
* SQLite 또는 JSONL 기반 영구 저장
* 중복 리뷰 처리

  * `skip`
  * `upsert`

---

## 3.2 데이터 정제

다음 규칙을 적용합니다.

* 필수 필드 검증
* 리뷰 텍스트 정규화
* 별점 1~5 범위 검증
* 날짜 형식 통일
* 지나치게 짧은 리뷰 필터링
* 중복 데이터 처리

데이터 저장 구조는 **Raw / Clean을 분리**합니다.

```text
raw
 ↓
clean
```

원본 데이터를 보존하면서 정제된 데이터를 별도로 관리하는 것을 원칙으로 합니다.

# 4. AI 감정 분석

정제된 리뷰 데이터를 AI API에 전달하여 다음 정보를 생성합니다.

```text
감정:
- positive
- negative
- neutral

confidence:
- 0.0 ~ 1.0
```

예시:

```json
{
  "sentiment": "negative",
  "confidence": 0.91
}
```

### 분석 대상 옵션

```bash
--all
--id
--unanalyzed
```

### 처리 원칙

* 이미 분석된 리뷰는 기본적으로 다시 분석하지 않음
* API 호출 실패 시 오류를 기록하고 해당 리뷰는 스킵
* API Key는 코드에 직접 작성하지 않음
* 환경변수 또는 설정 파일을 통해 관리

# 8. 비즈니스 인사이트

본 프로젝트의 핵심은 **차트를 만드는 것에서 끝나지 않는 것**입니다.

분석 결과를 비즈니스 관점에서 해석합니다.

예:

```text
전체 리뷰의 20%가 부정 리뷰로 분류됨.

시간별 추이를 확인한 결과 특정 기간 이후
부정 리뷰 비율이 증가함.

부정 리뷰의 TOP 키워드를 분석한 결과
'배송', '포장', '환불'이 주요 불만 사항으로 나타남.

→ 배송 및 포장 품질 개선을 우선 검토할 필요가 있음.
```

즉,

```text
데이터
 ↓
통계
 ↓
차트
 ↓
패턴 발견
 ↓
문제 파악
 ↓
비즈니스 인사이트
```

의 흐름을 완성합니다.

# 17. 개발 시 반드시 지켜야 할 원칙

잘못된 예:

```python
API_KEY = "sk-xxxxxxxx"
```

환경변수 또는 설정 파일을 활용합니다.

## ② 데이터는 메모리에만 저장하지 않는다

다음과 같은 단순 구조만 사용하는 것은 요구사항을 만족하지 못합니다.

```python
reviews = []
```

반드시 SQLite 또는 JSONL 등 영구 저장소를 사용합니다.

---

# 22. 프로젝트의 핵심 성공 기준

단순히 다음과 같은 결과를 만드는 것만으로는 충분하지 않습니다.

```text
긍정 62%
부정 20%
중립 18%
```

최종적으로는 다음 질문에 답할 수 있어야 합니다.

### 고객들은 무엇을 좋아하는가?

→ 긍정 키워드

### 고객들은 무엇을 불만스러워하는가?

→ 부정 키워드

### 문제가 언제 증가했는가?

→ 시간별 감정 추이

### 별점과 실제 감정은 어떤 관계가 있는가?

→ 별점-감정 분석

### 어떤 문제를 우선적으로 개선해야 하는가?

→ TOP N + AI 요약 + 비즈니스 인사이트

# 23. 최종 프로젝트 구조

전체 프로젝트의 핵심 흐름은 다음과 같습니다.

```text
                    ┌───────────────┐
                    │ CSV / Excel   │
                    └───────┬───────┘
                            ↓
                       [ IMPORT ]
                            ↓
                      RAW DATA
                            ↓
                       [ CLEAN ]
                            ↓
                     CLEAN DATA
                            ↓
                     [ AI ANALYZE ]
                            ↓
                 ┌──────────┴──────────┐
                 ↓                     ↓
            감정 / 신뢰도          키워드 / 요약
                 │                     │
                 └──────────┬──────────┘
                            ↓
                       [ STATISTICS ]
                            ↓
                 ┌──────────┼──────────┐
                 ↓          ↓          ↓
               감정       시간       별점
               분포       추이       분석
                 └──────────┼──────────┘
                            ↓
                       [ DASHBOARD ]
                            ↓
                    차트 + 인사이트
                            ↓
                       [ REPORT ]
                            ↓
                    TXT / Markdown
                            ↓
                       [ EXPORT ]
                            ↓
                 CSV / JSONL / Excel
```
